## 一、业务背景与目标

### 1.1 背景

本系统服务于日本 Arroz 公司（买方）与中国蕴杰公司（供应商）之间的外贸业务。双方围绕产品询价、报价、下单、发货进行协作。用户规模小（预计总用户数 < 50），访问量低，核心诉求是**流程清晰、数据可靠、操作简单**。

### 1.2 系统目标

| 序号 | 目标 | 说明 |
|------|------|------|
| G1 | 流程在线化 | 询单→报价→订单→发货→完成，全流程线上管理，替代邮件/微信沟通 |
| G2 | 数据可追溯 | 所有业务操作有审计日志，报价保留历史版本，删除数据可恢复 |
| G3 | 简单稳定 | 最小化技术复杂度，优先稳定性而非性能，部署在阿里云 |
| G4 | 双语界面 | 系统界面支持中文/日文切换，业务数据由用户自行填写（不做自动翻译） |

### 1.3 不做的事情

以下功能**明确不在本期范围内**，避免过度设计：

- 聊天消息自动翻译
- 询单/订单内容自动翻译
- 微信小程序
- 多供应商竞价（当前仅蕴杰一家供应商）
- 支付/财务模块
- 复杂的报表/BI 分析

## 三、核心业务流程

### 3.1 询单生命周期

```
                  ┌──────────┐
                  │  草稿     │
                  │  draft    │
                  └────┬─────┘
                       │ 买方发布
                       ▼
                  ┌──────────┐
          ┌───── │  已发布   │ ─────┐
          │      │ published │      │
          │      └──────────┘      │
          │ 买方作废                │ 供应商报价
          ▼                        ▼
   ┌──────────┐             ┌──────────┐
   │  已作废   │             │  已报价   │
   │ cancelled │             │  quoted   │
   └──────────┘             └────┬─────┘
                                 │ 买方转订单
                                 ▼
                           ┌──────────┐
                           │ 已转订单  │
                           │ converted │
                           └──────────┘
```

**规则：**
- 草稿 → 已发布：买方发布
- 已发布 → 已作废：买方作废（仅未被报价时）
- 已发布 → 已报价：供应商提交第一次报价
- 已报价 → 已转订单：买方基于报价创建订单
- 已报价状态下，询单**不可修改、不可作废**
- 管理员可在任何状态下**软删除**

### 3.2 报价模型

```
询单 1 ──── 报价版本 1（v1）
         ├── 报价版本 2（v2）
         └── 报价版本 3（v3）  ← 当前生效版本
```

- 一个询单对应一组报价，按版本号递增
- 每次修改报价 = 新增一个版本，旧版本保留只读
- 供应商可撤回报价（整组撤回，询单回到"已发布"状态）
- 买方可查看全部报价历史

### 3.3 订单生命周期

```
              ┌──────────┐
              │  待确认   │
              │  pending  │
              └────┬─────┘
                   │
         ┌─────────┼──────────┐
         │         │          │
    买方作废   供应商拒绝   供应商确认
         │         │          │
         ▼         ▼          ▼
   ┌──────────┐ ┌──────────┐ ┌──────────┐
   │  已作废   │ │  已拒绝   │ │  已确认   │
   │ cancelled │ │ rejected │ │ confirmed │
   └──────────┘ └──────────┘ └────┬─────┘
                                   │ 供应商开始生产
                                   ▼
                             ┌──────────┐
                             │  生产中   │
                             │production │
                             └────┬─────┘
                                  │ 供应商发货
                                  ▼
                             ┌──────────┐
                             │  已发货   │
                             │ shipped   │
                             └────┬─────┘
                                  │ 买方确认收货
                                  ▼
                             ┌──────────┐
                             │  已完成   │
                             │ completed │
                             └──────────┘
```

**规则：**
- 仅**待确认**状态可被买方作废或供应商拒绝
- 确认后不可逆（不可作废）
- 供应商发货时须上传单据（发票、运单、材质单等）作为订单附件
- 买方确认收货后订单完成，流程结束

### 3.4 聊天模型

- 聊天**绑定到具体的询单或订单**，不存在独立聊天
- 询单转为订单后，两个聊天各自独立，不迁移
- 所有与该询单/订单相关的用户均可参与聊天

## 八、与 V1 的主要变更

| 变更项 | V1 | V2 | 原因 |
|--------|----|----|------|
| 聊天翻译 | 有 | 移除 | 简化系统，降低复杂度和外部依赖 |
| 内容翻译 | 有 | 移除 | 同上 |
| Redis | 有 | 移除 | JWT 无状态，不需要 session 缓存 |
| Socket.IO | 有 | 待定（设计阶段决定） | 可用轮询替代，降低复杂度 |
| 报价模型 | 1对1可覆盖 | 1对多版本化 | 保留历史，数据可追溯 |
| 删除策略 | 硬删除 | 软删除+回收站 | 数据安全可恢复 |
| 审计日志 | 无 | 有 | 操作可追溯 |
| 数据导出 | 无 | Excel 导出 | 业务需要 |
| 密码管理 | 无 | 修改+重置 | 基础安全需求 |
| 文件存储 | 本地磁盘 | 阿里云 OSS | 云端部署，数据持久化 |
| 供应商权限 | 可作废任何询单/订单 | 仅可撤回自己的报价、拒绝待确认订单 | 修复权限漏洞 |
| 角色命名 | customer/buyer 混用 | 统一为 buyer | 消除歧义 |
