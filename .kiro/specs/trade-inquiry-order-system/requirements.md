# 需求文档

## 介绍

本系统是一个专为日本Arroz公司（买方）和中国蕴杰公司（供应商）之间外贸业务设计的询单订单管理平台。系统采用B/S架构，支持浏览器访问，并保留未来支持微信小程序的扩展性。系统提供完整的询单到订单的业务流程管理，包括询单发布、报价回复、订单确认、状态跟踪和文件管理等功能。

## 需求

### 需求 1 - 用户管理系统

**用户故事：** 作为超级管理员，我希望能够管理所有用户账户，以便控制系统访问权限和用户角色分配。

#### 验收标准

1. 当系统初始化时，系统应创建默认超级管理员账户（用户名：admin，密码：admin123）
2. 当超级管理员登录时，系统应在dashboard页面提供用户管理入口
3. 当超级管理员访问用户管理页面时，系统应显示所有用户列表并支持添加、修改、删除操作
4. 当创建用户时，系统应要求指定用户角色（Arroz买方用户或蕴杰供应商用户）
5. 当用户登录时，系统应根据用户角色显示相应的功能权限

### 需求 2 - 询单管理功能

**用户故事：** 作为Arroz公司员工，我希望能够发布和管理询单，以便向供应商询价并获得报价信息。

#### 验收标准

1. 当买方用户发布询单时，系统应生成唯一询单号并包含产品名称、材料种类、尺寸规格、特殊要求、数量等基本信息
2. 当发布询单时，系统应支持上传附件（图片、PDF、3D文件等格式）
3. 当询单未被供应商回复时，买方用户应能够修改或作废自己创建的询单
4. 当询单已被供应商回复后，买方用户应无法再修改或作废该询单
5. 当买方用户浏览询单时，系统应显示所有询单但只允许操作自己创建的询单
6. 当需要删除询单时，只有超级管理员应具有删除权限

### 需求 3 - 报价回复功能

**用户故事：** 作为蕴杰公司员工，我希望能够回复买方询单并提供报价，以便完成商务洽谈。

#### 验收标准

1. 当供应商用户查看询单时，系统应显示所有待回复和已回复的询单
2. 当回复询单时，系统应要求提供单价、总价、工期等报价信息
3. 当供应商回复询单后，系统应通知买方用户有新的报价
4. 当供应商已回复询单时，系统应允许供应商修改报价信息
5. 当供应商需要时，系统应允许供应商作废已回复的询单

### 需求 4 - 订单创建和管理

**用户故事：** 作为买方用户，我希望能够创建正式订单（通过询单转换或独立创建），以便进行后续的订单跟踪。

#### 验收标准

1. 当买方对报价满意时，系统应支持将询单转换为正式订单并生成唯一订单号
2. 当买方需要时，系统应支持独立创建订单（无需先创建询单），包含订单号、产品名称、材料种类、尺寸规格、特殊要求、单价、数量、总价、附件等完整信息
3. 当订单创建后（无论通过询单转换还是独立创建），系统应通知供应商确认订单
4. 当供应商确认订单后，买方应无法再作废该订单
5. 当订单未被供应商确认时，买方应能够作废订单
6. 当买方浏览订单时，系统应显示所有订单但只允许操作自己创建的订单

### 需求 5 - 订单状态跟踪

**用户故事：** 作为供应商用户，我希望能够更新订单状态，以便买方了解订单进展情况。

#### 验收标准

1. 当供应商确认订单时，系统应将订单状态更新为"已确认"
2. 当供应商开始生产时，系统应支持将状态更新为"生产中"
3. 当供应商发货时，系统应支持上传发票、运单、材质单等文件并更新状态为"已发货"
4. 当买方收货后，系统应支持买方确认订单完成
5. 当订单状态变更时，系统应通知相关用户

### 需求 6 - 订单内沟通功能

**用户故事：** 作为系统用户，我希望能够在订单或询单内进行沟通，以便解决业务相关问题。

#### 验收标准

1. 当用户查看订单或询单详情时，系统应提供聊天功能入口
2. 当用户发送消息时，系统应实时显示消息并通知对方
3. 当有新消息时，系统应在订单或询单列表中显示未读消息提示
4. 当查看聊天记录时，系统应按时间顺序显示所有消息
5. 当发送消息时，系统应显示发送者信息和时间戳
6. 当用户查看聊天消息时，系统应在每条消息旁提供翻译按钮
7. 当用户点击翻译按钮时，系统应将消息内容翻译为目标语言（中文↔日文）并显示翻译结果
8. 当显示翻译结果时，系统应同时保留原文和译文，便于用户对比理解

### 需求 7 - 多语言支持

**用户故事：** 作为系统用户，我希望能够一键切换中日文界面，以便更好地理解和使用系统。

#### 验收标准

1. 当用户点击语言切换按钮时，系统应立即切换界面语言（中文/日文）
2. 当切换语言时，系统应保存用户的语言偏好设置
3. 当用户重新登录时，系统应使用用户上次选择的语言
4. 当显示订单和询单内容时，系统应支持中日文内容的正确显示
5. 当系统提示信息时，系统应使用当前选择的语言显示

### 需求 8 - 文件附件管理

**用户故事：** 作为系统用户，我希望能够上传和管理各种格式的文件附件，以便完善订单和询单信息。

#### 验收标准

1. 当上传附件时，系统应支持图片、PDF、3D文件等多种格式
2. 当上传文件时，系统应验证文件格式和大小限制
3. 当查看附件时，系统应提供预览或下载功能
4. 当删除附件时，系统应要求确认操作
5. 当文件上传失败时，系统应显示明确的错误信息

### 需求 9 - 权限控制系统

**用户故事：** 作为系统管理员，我希望系统能够严格控制用户权限，以便保证数据安全和业务流程的正确性。

#### 验收标准

1. 当买方用户操作时，系统应只允许其修改自己创建的询单和订单
2. 当供应商已回复询单或确认订单后，系统应禁止买方用户作废相关记录
3. 当供应商用户操作时，系统应允许其作废任何询单或订单
4. 当删除操作时，系统应只允许超级管理员执行
5. 当用户尝试无权限操作时，系统应显示权限不足的提示信息
